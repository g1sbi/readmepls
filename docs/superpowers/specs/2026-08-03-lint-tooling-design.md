# Restore lint tooling — design

**Date:** 2026-08-03
**Status:** approved, not yet implemented

## Problem

`pnpm lint` (`prettier --check . && eslint .`) has never worked in this repo.

- **ESLint fails outright.** `devDependencies` pins `eslint@^9.0.0`, but no
  `eslint.config.js` exists anywhere in the tree, and no legacy `.eslintrc.*`
  either. ESLint 9 dropped `.eslintrc` support, so it exits non-zero before
  linting a single file.
- **Prettier has no config and no ignore file.** It therefore walks everything
  — `pnpm-lock.yaml`, `CHANGELOG.md`, PocketBase migrations — and reports 228
  files on `develop`.
- **All 107 `.svelte` files are invisible to Prettier.** Without
  `prettier-plugin-svelte` it cannot infer a parser for `.svelte`; run against a
  directory it silently skips them. The real unformatted count is ~340 once the
  plugin lands, not 228.
- **Nothing in CI catches this.** The only workflows are `docker-publish.yml`
  and `release-please.yml`. Neither runs lint, typecheck, or tests — which is
  how the missing configs went unnoticed.

CLAUDE.md documents `pnpm lint` as a project command, so the documented
workflow and the repo state disagree.

## Goals

1. `pnpm lint` runs clean and stays meaningful.
2. Svelte files are actually covered.
3. The regression cannot silently recur.

## Non-goals

- Rules stricter than `recommended`. Type-aware linting
  (`recommendedTypeChecked`) is deliberately deferred: it needs full-type-graph
  wiring, runs slowly, and `pnpm typecheck` already covers type correctness.
- Reformatting ignored directories.
- Mass-suppressing genuine ESLint violations. If `recommended` surfaces real
  problems, they get reported and triaged, not `eslint-disable`d.

## Design

### 1. Prettier

Add `.prettierrc` and register `prettier-plugin-svelte` so `.svelte` files are
parsed rather than skipped:

```json
{
  "plugins": ["prettier-plugin-svelte"],
  "overrides": [{ "files": "*.svelte", "options": { "parser": "svelte" } }]
}
```

Formatting options are left at Prettier's defaults — double quotes, semicolons,
2-space indent, 80-column print width, trailing commas. That is what the
already-conforming portion of the tree uses, so pinning anything else would
widen the reformat for no gain. The config exists to register the plugin, not
to relitigate style.

Add `.prettierignore`:

| Ignored | Why |
| --- | --- |
| `pnpm-lock.yaml` | generated by pnpm |
| `CHANGELOG.md` | release-please owns this file |
| `.svelte-kit/`, `dist/`, `node_modules/` | build output |
| `pocketbase/pb_migrations/`, `pocketbase/pb_hooks/` | PocketBase's own JS dialect, not our style |
| `.superpowers/` | tooling scratch, not project source |
| `assets/_banner.html` | design source of truth; reformatting churns the palette reference |

### 2. ESLint

Flat `eslint.config.js`, composed in this order:

```
js.configs.recommended
tseslint.configs.recommended      // no type-aware pass
svelte.configs.recommended
eslint-config-prettier            // last — disables stylistic rules that fight Prettier
```

`ignores` mirrors `.prettierignore` so the two tools agree on scope.

New devDependencies: `typescript-eslint`, `eslint-plugin-svelte`,
`eslint-config-prettier`, `prettier-plugin-svelte`, `svelte-eslint-parser`.

### 3. The reformat

Sequenced as three commits so the mechanical change is isolated and
independently revertible:

1. `chore:` — configs, ignore files, devDependencies
2. `style:` — the repo-wide reformat (~340 files), nothing else
3. `chore:` — `.git-blame-ignore-revs` containing the reformat SHA

The full test suite (199 files / 762 tests) runs after the reformat. It is the
safety net proving the change is purely textual.

### 4. CI

New `.github/workflows/ci.yml`, on push and pull_request: install → lint →
typecheck → test.

Two environment facts the workflow must handle, both discovered during design:

- **Tests spawn a real PocketBase binary.**
  `packages/core/src/pb/test-harness.ts` resolves
  `process.env.PB_BIN ?? "pocketbase/pocketbase"`, and that path is gitignored.
  CI downloads it, reading the pinned version out of `pocketbase/Dockerfile`
  (`ARG PB_VERSION=0.39.4`) rather than duplicating the number, so there stays
  one source of truth.
- **`.svelte-kit/` is gitignored with no `prepare` script.** `apps/web/tsconfig.json`
  and `apps/site/tsconfig.json` both `extends` `./.svelte-kit/tsconfig.json`,
  which only exists after `svelte-kit sync` runs. On a fresh checkout Vite
  cannot resolve that extends chain, and **all 84 web test files fail to
  collect** (verified by moving the directory aside: `84 failed (84)`,
  `Tests no tests`). Root `pnpm typecheck` is unaffected — `tsconfig.json`
  includes only `packages/types/src`, `packages/core/src`, and
  `apps/worker/src`, deliberately excluding the SvelteKit apps. So this breaks
  the **test** step, not typecheck. Add `"prepare": "svelte-kit sync"` to
  `apps/web/package.json` and `apps/site/package.json` so `pnpm install` is
  self-sufficient; this also removes the fresh-worktree bootstrap step
  currently done by hand.

## Risks

The reformat is the only part touching application source. It is mechanical,
gated by the test suite, and confined to its own commit.

If `tseslint.configs.recommended` surfaces a large number of genuine violations
across the 381 TS files, implementation stops and reports the list for a
decision rather than proceeding.

## Verification

- `pnpm lint` exits 0
- `pnpm typecheck` exits 0
- `pnpm test` — 199 files / 762 tests pass, unchanged from before the reformat
- `git blame` on a reformatted file attributes lines to their real authors once
  `blame.ignoreRevsFile` is configured
